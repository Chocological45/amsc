# Adaptive Mask Selection and Composition (AMSC)

Training and evaluation code for the CT28 and MG16 experiments. Continual
World experiments use the separate `amsc_cw/experiments/meta-world/HPC_CW10_COMMANDS.md` for the CW10 configurations.

The supplementary archive uses the following layout:

```text
amsc/    CT28/MG16 training, environment configurations, and metrics
amsc_cw/          CW10 training and execution instructions
```

## Main Experiments

The commands below run seeds 86--92 sequentially on one visible GPU. To run
seeds in parallel, launch separate processes with distinct
`CUDA_VISIBLE_DEVICES` values. Each seed runs the complete curriculum.

Both configurations use state--action--reward embeddings, normalized sparsemax
retrieval, L2-STE, fixed sparsemax composition, and no competence gate.
The historical runs used the legacy EMA update; the compatibility flag below
preserves it. Omitting it uses the revised update that normalizes each new
embedding before averaging.

### CT28

```bash
export CUDA_VISIBLE_DEVICES=0
for seed in 86 87 88 89 90 91 92; do
    python train_ctgraph.py ll_supermask \
        --seed "$seed" --exp_id amsc --pathheader reproduce/ct28 \
        --env_config_path env_configs/ct28/seed1/meta_ctgraph_ct28_interleaved.json \
        --max_steps 51200 --new_task_mask linear_comb \
        --disable_task_label_input \
        --detect_num_samples 128 --detect_reference_num 50 \
        --detect_frequency 1 --select_frequency 1 \
        --embedding_ema 0.5 --detect_reference_seed 98 --legacy_wte_ema \
        --selection_soft_temperature 1.0 \
        --selection_disable_competence_gate \
        --mask_score_normalization l2_ste --mask_score_normalize_current \
        --selection_sparsemax_fixed_composition || exit $?
done
```

### MG16

The main MG16 configuration uses 1,024 embedding samples and 50 reference
samples. Older presets and representation-study runs may use 512 samples.

```bash
export CUDA_VISIBLE_DEVICES=0
for seed in 86 87 88 89 90 91 92; do
    python train_minigrid.py ll_supermask \
        --seed "$seed" --exp_id amsc --pathheader reproduce/mg16 \
        --env_config_path "env_configs/minigrid_object_remap_seed${seed}.json" \
        --max_steps 512000 --new_task_mask linear_comb \
        --disable_task_label_input \
        --detect_num_samples 1024 --detect_reference_num 50 \
        --detect_frequency 1 --select_frequency 5 \
        --embedding_ema 0.5 --detect_reference_seed 98 --legacy_wte_ema \
        --selection_soft_temperature 1.0 \
        --selection_disable_competence_gate \
        --mask_score_normalization l2_ste --mask_score_normalize_current \
        --selection_sparsemax_fixed_composition || exit $?
done
```

CT28 evaluates every 10 PPO iterations and MG16 every 20, using 10 episodes
per task. Each PPO iteration collects 512 environment steps.

## Outputs

Runs are saved under `log/reproduce/ct28/` and `log/reproduce/mg16/`, with
a separate experiment directory and timestamp for each run.

- `eval_metrics.csv`: evaluation returns used to calculate paper metrics.
- `task_similarities.csv`: task similarities and retrieval diagnostics.
- `beta_composition.csv`: mask-composition diagnostics.
- `env_config.json`: the environment configuration used.
- `config.json`: saved training configuration; written when training finishes.
- Checkpoint files: saved policy parameters and task masks.

Keep only the intended completed runs under each metric input root. Repeated
launches create additional timestamped runs rather than replacing earlier ones.

## Calculate AUC, FWT, and FGT

Use `significance_test_metrics_latex.py`, included here from the paper analysis
code. The older `scripts/significance_test_metrics.py` does not implement all paper
metric definitions.

FWT requires independently trained single-task expert logs with matching tasks
and seeds. Set the expert paths below to those logs; they are not generated by
the main AMSC commands.

```bash
CT28_EXPERT_ROOT=/path/to/ct28-single-task-experts
MG16_EXPERT_ROOT=/path/to/mg16-single-task-experts

python significance_test_metrics_latex.py \
    --ref AMSC --methods AMSC=log/reproduce/ct28 \
    --expert-root "$CT28_EXPERT_ROOT" \
    --task-order-config env_configs/ct28/seed1/meta_ctgraph_ct28_interleaved.json \
    --performance-normalization scalar \
    --metric auc_cw fwt fgt_cw --round-dp 2 > ct28_metrics.tex

python significance_test_metrics_latex.py \
    --ref AMSC --methods AMSC=log/reproduce/mg16 \
    --expert-root "$MG16_EXPERT_ROOT" \
    --task-order-config env_configs/minigrid_object_remap_seed86.json \
    --performance-normalization minigrid_shortest_path \
    --metric auc_cw fwt fgt_cw --round-dp 2 > mg16_metrics.tex
```

`auc_cw` measures area under each task's learning curve during its own training
interval. `fwt` compares learning with the single-task reference.
`fgt_cw` measures the drop from end-of-task performance to final performance.
MG16 returns are normalized by task-specific shortest-path returns.

The script reports means and bootstrap confidence intervals. Add other
`Name=log/root` entries to `--methods` for comparisons. For the paired
one-sided main comparisons, add
`--table-test sign_flip --alternative greater greater less`.
Use `--per-task-metrics-table --per-task-metrics-ci` for per-task tables.
Run `python significance_test_metrics_latex.py --help` for further options.

## Launcher and Additional Experiments

`launcher.py` contains composition ablations, quantization experiments, and
hyperparameter sweeps. Inspect commands before execution:

```bash
python launcher.py --env ctgraph_l2_ste_sparsemax_no_comp --dry-run
python launcher.py --env minigrid_sensitivity_all --dry-run
```

The launcher contains machine-specific MIG UUIDs. Its `--gpu` argument selects
a configured device group, not an ordinary CUDA device number. Configure those
groups for your machine before using it; the direct training commands above
avoid this dependency.

`--skip-completed` skips completed runs but does not resume an interrupted
training checkpoint. Incomplete runs are restarted. Use a fresh output root
or remove incomplete runs from the metric input root before aggregation.

Training utilities are adapted from Mask-LRL and DeepRL. Existing license and
attribution files are retained.

## CW10

Use a separate Python 3.10 environment for CW10. From the archive root:

```bash
cd amsc_cw/experiments/meta-world
conda create -n amsc-cw python=3.10
conda activate amsc-cw
export PYTHONNOUSERSITE=1
python -m pip install -r requirements.txt
python launcher.py --help
```

`HPC_CW10_COMMANDS.md` specifies the paper configurations and baseline commands.
For SLURM, submit from this directory, set `PROJECT_DIR="$PWD"`, and override
the account, partition, CUDA module, and conda environment for your cluster.
The supplied account and partition are examples, not portable cluster settings.
`posthoc_eval_checkpoints.py` remains beside the models it loads.

Calculate CW metrics from the online evaluation CSVs, replacing the tag
prefixes with those used for your method and seed-matched from-scratch runs:

```bash
python compute_metrics.py --runs-root runs \
    --model amsc-fullnet --tag-prefix YOUR_AMSC_TAG \
    --reference-tag-prefix YOUR_SIMPLE_TAG --out cw10_metrics.json
```

This uses all 20 evaluations per task at 50,000-step intervals. AUC averages
active-task success; FWT compares trapezoidal areas against matched scratch
runs; FGT compares task-end and final success. FWT is undefined for reference
headroom below 0.001, and these task values are excluded from the seed mean.
The output includes per-seed/per-task values and 95% bootstrap intervals.
Use the architecture-matched scratch reference for each baseline.

Ancillary analysis tools are in `amsc/scripts/` and `amsc_cw/scripts/`.
Run them from the corresponding training directory, for example
`python scripts/analyze_mask_quantization.py --help` from `amsc/`.
Historical shell pipelines and saved command-output artifacts are retained
under `scripts/` for reference, not as reproduction entry points.
